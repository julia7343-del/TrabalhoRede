Ferramentas de Linha de Comando

ping <host>

Testa conectividade IP enviando pacotes ICMP Echo Request. Mede tempo de resposta (latência) e perda de pacotes.

ipconfig /all

Exibe detalhes de IP, máscara de sub-rede, gateway padrão, endereço MAC e servidores DNS do host.

nslookup <dominio>

Consulta os servidores DNS para verificar a resolução de nomes em endereços IP e identificar falhas de resolução.

tracert <destino>

Mapeia a rota até o destino, mostrando todos os saltos (roteadores) no caminho e onde ocorre interrupção.

arp -a

Exibe a tabela ARP local que mapeia endereços IP conhecidos para seus respectivos endereços físicos (MAC).

netstat -an

Lista todas as conexões de rede ativas e portas de escuta do sistema operacional.

Camada 1 - Física

1. Cabo de Rede Desconectado ou Defeituoso

O que está acontecendo?

O sistema operacional indica que a mídia de rede está desconectada. A interface não possui link elétrico/óptico com o switch ou roteador.

Causas Prováveis

  • Cabo desconectado da placa de rede ou da tomada de parede.
  • Conector RJ-45 com trava quebrada ou crimpagem defeituosa.
  • Rompimento interno nos pares trançados do cabo.
  • Porta do switch/roteador queimada ou desativada administrativamente.

Comandos para Identificação

# Windows:
ipconfig /all

# Linux:
ip link show

Resultado típico: "Estado da mídia: Mídia desconectada" ou "NO-CARRIER".

Como Resolver

  1. Verifique se o cabo está devidamente encaixado até escutar o clique da trava.
  2. Observe se os LEDs (Link/Activity) da placa de rede do computador piscam.
  3. Substitua o cabo por um testado (Cat5e/Cat6).
  4. Conecte o cabo em outra porta do switch ou roteador.
Camada 3 - Rede

2. Endereço IP Incorreto / Sub-rede Incompatível

O que está acontecendo?

O computador está fisicamente conectado, mas não consegue conversar com o Gateway nem com outros computadores da LAN por estar configurado em uma sub-rede diferente.

Causas Prováveis

  • Atribuição manual de IP estático incorreto (ex: IP 10.0.0.15 numa rede 192.168.1.0/24).
  • Máscara de sub-rede configurada incorretamente (ex: 255.255.255.240 em vez de 255.255.255.0).
  • Falha do servidor DHCP ao não renovar as configurações de IP.

Comandos para Identificação

ipconfig
ping 192.168.1.1

Resultado típico: "Esgotado o tempo limite do pedido" ou "Host de destino inacessível".

Como Resolver

  1. Configure a interface de rede para obter IP automaticamente via DHCP.
  2. Caso utilize IP fixo, ajuste o IP para a mesma sub-rede do roteador com a máscara correta.
  3. Execute os comandos de renovação: ipconfig /release e ipconfig /renew.
Camada 2/3 - Enlace e Rede

3. Conflito de Endereço IP

O que está acontecendo?

Dois dispositivos na mesma rede local estão utilizando o mesmo endereço IP, resultando em oscilações e queda de conexão para ambos.

Causas Prováveis

  • Atribuição manual de um IP fixo que já faz parte do escopo dinâmico do servidor DHCP.
  • Dois dispositivos configurados manualmente com o mesmo IP.
  • Falha na tabela de leases do servidor DHCP.

Comandos para Identificação

arp -a
# Verifique se o endereço IP aparece associado a múltiplos endereços MAC na tabela.

Como Resolver

  1. Libere e renove o IP via linha de comando: ipconfig /release e depois ipconfig /renew.
  2. Em IPs estáticos, altere a máquina para um endereço livre ou configure uma reserva DHCP no roteador pelo endereço MAC.
Camada 7 - Aplicação

4. Problema de Resolução de Nome (DNS)

O que está acontecendo?

Você consegue acessar serviços digitando o endereço IP direto (ex: http://1.1.1.1), mas os navegadores não carregam URLs de domínio (ex: www.google.com).

Causas Prováveis

  • Servidor DNS configurado está fora do ar ou inacessível.
  • Endereço do servidor DNS incorreto na placa de rede.
  • Cache de DNS local corrompido.

Comandos para Identificação

nslookup www.google.com
ping 8.8.8.8

Se o ping 8.8.8.8 funcionar, mas o nslookup falhar, confirma-se o problema exclusivo no serviço de DNS.

Como Resolver

  1. Limpe o cache do DNS local: ipconfig /flushdns.
  2. Altere os servidores DNS da interface para servidores públicos confiáveis:
    • Cloudflare: 1.1.1.1 e 1.0.0.1
    • Google: 8.8.8.8 e 8.8.4.4
Camada 3 - Roteamento

5. Computador sem Acesso à Internet (Gateway)

O que está acontecendo?

A máquina consegue se comunicar localmente (ex: acessa impressoras e outros computadores), mas não consegue sair para redes externas (Internet).

Causas Prováveis

  • Gateway Padrão (Default Gateway) não configurado no host.
  • IP do Gateway incorreto.
  • Roteador de borda sem conexão WAN com o Provedor de Internet (ISP).

Comandos para Identificação

ipconfig
ping 192.168.1.1
tracert 8.8.8.8

Como Resolver

  1. Verifique se o IP do Gateway Padrão corresponde ao IP do roteador local.
  2. Testar conexão do Gateway reiniciando o modem/roteador.
  3. Entrar em contato com o Provedor de Internet para checar instabilidade externa na linha WAN.
